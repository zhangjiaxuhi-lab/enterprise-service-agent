# 企业 SaaS 账号排障指南（账号 FAQ）

> 适用范围：企业版 SaaS 控制台账号登录、授权与安全策略问题
> 维护部门：客户成功中心 / 一线技术支持组
> 文档版本：v1.0

---

## 1. 常见错误码总览

| 错误码 | 含义 | 归因层级 | 一线可自助解决 |
|--------|------|----------|----------------|
| 401 Unauthorized | 未授权：身份凭证缺失、过期或无效 | 认证层 | 是 |
| 403 Forbidden | 权限不足：已认证但无该资源操作权限 | 授权层 | 部分（需管理员配合） |
| 429 Too Many Requests | 请求频率超限 | 限流层 | 是 |
| 账号锁定 (Account Locked) | 密码连续输错触发安全策略 | 安全策略层 | 是（可自助解锁或等待） |

---

## 2. 401 未授权（Unauthorized）

### 2.1 典型报错文案
- `401 Unauthorized: invalid or expired token`
- `登录状态已失效，请重新登录`
- `API key not found / API key is invalid`

### 2.2 根本原因
1. **访问令牌（Access Token）过期**：企业版默认有效期 **2 小时**，刷新令牌（Refresh Token）有效期 **7 天**。
2. **密码被修改或管理员强制下线**：改密后所有历史令牌立即失效。
3. **客户端时间不同步**：本地时间与标准时间偏差超过 **5 分钟** 会导致 JWT 校验失败。
4. **多环境密钥混用**：把测试环境（Sandbox）的 Key 用于生产环境，或反之。
5. **单点登录（SSO）会话过期**：企业 SSO 侧会话已登出，本地仍保留旧会话。

### 2.3 标准解决步骤（按顺序执行）
1. **退出并重新登录**：点击右上角头像 →「退出登录」，完全关闭浏览器标签页后重新访问控制台。
2. **清理浏览器缓存与 Cookie**：清除该域名下全部 Cookie；或使用无痕窗口验证是否为本地缓存问题。
3. **校验系统时间**：确认操作系统已开启「自动同步网络时间」，偏差需小于 5 分钟。
4. **重新生成 API Key**：控制台 →「开发者中心」→「API 密钥」→ 吊销旧密钥并创建新密钥，随后更新到 `.env` 文件。
5. **检查环境变量拼接**：确认 `Authorization: Bearer <TOKEN>` 中无多余空格、引号或换行符。
6. **确认环境正确**：核对请求的 Base URL 属于生产还是测试环境。

### 2.4 升级判定条件
若完成上述 6 步后仍返回 401，且满足以下任一条件，应升级至二线：
- 同一账号在**多个浏览器**均复现 401；
- 认证服务端出现 **5xx** 错误码；
- 企业 SSO（SAML / OIDC）配置近期发生变更。

### 2.5 客服处理规则
- **一线**：可指导用户完成自助步骤 1–6，可代为清理服务端缓存会话（需二次验证身份）。
- **禁止**：不得向用户索要或记录**明文密码**；不得通过聊天工具传输 API Key。
- **必填信息**：处理 401 工单时必须收集 `user_id`、报错截图、报错发生时间（含时区）、请求 ID（Request ID）。
- **响应时效**：401 类问题一线首次响应 **≤ 15 分钟**；升级二线后 **≤ 2 小时** 给出结论。

## 3. 403 权限不足（Forbidden）

### 3.1 典型报错文案
- `403 Forbidden: insufficient permissions`
- `您没有访问该资源的权限`
- `Role does not allow this action`

### 3.2 根本原因
1. **角色（Role）不含目标权限**：企业版预置角色为「超级管理员 / 部门管理员 / 普通成员 / 只读访客」。
2. **资源未授权给该成员**：项目、数据集、报表等资源默认为私有，需显式授权。
3. **IP 白名单限制**：企业安全策略仅允许办公网出口 IP 访问。
4. **套餐额度不足**：功能属于更高版本套餐（如旗舰版专属的审计日志）。
5. **数据权限范围（Data Scope）限制**：仅能查看本部门数据，跨部门访问被拒绝。

### 3.3 标准解决步骤（按顺序执行）
1. **确认当前角色**：控制台 →「企业管理」→「成员与角色」，记录当前账号绑定的角色。
2. **比对权限矩阵**：核对所需操作是否在该角色权限范围内。
3. **提交授权申请**：由**企业超级管理员**在「成员管理」中为账号追加对应角色或资源授权。
4. **配置资源级授权**：在目标资源（项目/数据集）的「共享设置」中把该成员加入协作者并赋予查看或编辑权限。
5. **核对 IP 白名单**：若使用非办公网络，请管理员将当前公网 IP 加入白名单。
6. **确认套餐版本**：若功能属于高版本套餐，引导客户或销售确认升级事宜。
7. **重新登录生效**：权限变更后建议用户重新登录，确保新权限写入会话。

### 3.4 升级判定条件
- 需要**跨部门数据授权**或涉及**合规审计**的权限申请；
- 管理员确认权限已正确配置但仍返回 403；
- 涉及**套餐升级 / 合同变更**的商务类权限需求。

### 3.5 客服处理规则
- **一线权限边界**：一线**无权**直接修改客户企业内的角色与权限，只能提供操作指引或提交内部工单。
- **双人复核**：任何权限变更必须由**客户方超级管理员**在系统内自行操作，或由二线在获得**工单内书面授权**后执行。
- **留痕要求**：所有 403 授权类工单必须留存「申请人、审批人、变更时间、变更前后角色」四项记录。
- **安全红线**：严禁为提高效率而临时授予「超级管理员」角色，必须遵循最小权限原则。
- **响应时效**：403 类问题一线首次响应 **≤ 30 分钟**；涉及管理员审批的，**≤ 4 小时** 闭环。

## 4. 密码连续输错导致账号锁定

### 4.1 触发规则
- 连续输错密码 **5 次**，账号自动锁定；
- 锁定时长：**15 分钟**（自动解锁）；
- 连续触发 **3 轮**（即 1 小时内被锁定 3 次），将升级为**人工解锁**，需联系管理员或客服。

### 4.2 典型报错文案
- `账号已被锁定，请 15 分钟后重试`
- `Account locked due to too many failed login attempts`

### 4.3 标准解决步骤（按顺序执行）
1. **确认锁定状态**：告知用户此为安全策略，非账号异常。
2. **等待自动解锁**：若为首次或第二次锁定，等待 **15 分钟** 后使用正确密码登录（等待期间不要重复尝试，否则计时重置）。
3. **使用「忘记密码」自助重置**：点击登录页「忘记密码」→ 输入注册邮箱/手机号 → 收取验证码 → 设置新密码。
4. **密码复杂度要求**：长度 **≥ 10 位**，且必须同时包含**大写字母、小写字母、数字、特殊符号**中的至少三类；不得与最近 **3 次** 历史密码重复。
5. **人工解锁**：若已被升级为人工解锁，由**企业超级管理员**在「成员管理」中执行「解锁账号」，或由一线核实身份后提单转二线处理。
6. **建议启用多因素认证（MFA）**：解锁后引导用户绑定 MFA，可显著降低暴力破解风险。

### 4.4 身份核验要求（重要）
人工解锁前，**必须**完成以下核验中的**至少两项**：
- 提供注册企业名称与 `user_id`；
- 使用**注册预留邮箱**回复确认；
- 使用**注册预留手机号**接收并回填验证码；
- 提供最近一次成功登录的时间与大致 IP 归属地。

### 4.5 升级判定条件
- 用户无法访问注册邮箱/手机号，需走**人工申诉**流程；
- 疑似**暴力破解或账号被盗**：日志中存在异地、高频失败登录；
- 同一企业**批量账号**同时被锁定（可能是撞库攻击）。

### 4.6 客服处理规则
- **禁止**：任何情况下不得向用户询问、记录或代填**明文密码**。
- **禁止**：不得跳过身份核验直接解锁账号。
- **必填信息**：`user_id`、注册邮箱或手机号、锁定发生时间、失败登录次数。
- **安全事件响应**：若判定为账号被盗或撞库，需在 **30 分钟** 内同步安全团队，并强制该账号下线、重置密码、要求启用 MFA。
- **响应时效**：锁定类问题一线首次响应 **≤ 15 分钟**；人工申诉类 **≤ 24 小时** 给出结论。

## 5. 账号类工单必填字段

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| `user_id` | 用户账号唯一标识 | 必填 |
| `issue_type` | 问题类型，账号类固定为 `account` | 必填 |
| `description` | 问题详细描述，需含报错码、时间、已尝试步骤 | 必填 |
| 报错截图 | 含 Request ID 的完整截图 | 建议提供 |
| 发生时间 | 含时区，精确到分钟 | 建议提供 |
